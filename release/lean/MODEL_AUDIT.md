# Аудит відповідності означень Lean тексту моделі препринту

Звірка означень `RAM.lean` (255 рядків) і `Goal.lean` (86 рядків) з розділом
`\subsection{Arithmetic model and main result}` (`sections/introduction.tex`,
мітка `sec:model`) і теоремою `thm:main` препринту. Коміт каталогу 301488868,
HEAD fd4aeeb. Це аудит **означень** (що саме стверджено), а не доведення
(його перевіряє ядро Lean; `#print axioms` дає лише propext, Classical.choice,
Quot.sound) і не семантики вартості як моделі фізичної RAM.

## Корінь і матриця (FourierCircuit/Core.lean)

| Препринт | Lean | Збіг |
|---|---|---|
| ζ залежить від n, явно заданий корінь | `zeta n = Complex.exp (2πi/n)` — первісний корінь порядку n | так |
| F_n — матриця DFT | `fourierMatrix n j k = zeta n ^ (j·k)` | так |
| алгоритм обчислює F_n·x точно | `dft n x = fun j => ∑ k, (root n)^(j·k)·x k`, root = zeta; збігається з `fourierMatrix.mulVec x` | так |

## Модель вартості (RAM.lean) ↔ sec:model

| Твердження моделі препринту | Конструкція Lean | Збіг |
|---|---|---|
| комплексні регістри і цілочисельні адресні регістри | `Ty`: `c : Paint → Ty` (`Ty.T (c _) = ℂ`), `w` (`Ty.T w = ℕ`), масив `a`, пара `p` | так |
| скалярні й даних регістри розділені | `Paint = scalar \| left \| right \| both`; `sc := c scalar` | так |
| операція поля коштує одиницю | `Atom.run` для add/sub/scale/cross → `Bill.one`; inv має окремий запис work=1 і valid x≠0 | так |
| лише додавання, віднімання і множення на підготовлені скаляри на вході | атоми `add`, `sub`, `scale (p sc (c t))`; добуток даних лише `cross` | так |
| ділення — лише при підготовці скалярів, знаменник доведено ненульовий | `inv : Atom allow sc sc` (лише на `sc`); `run .inv x = ⟨x⁻¹,1,0, x ≠ 0⟩` — `x ≠ 0` у полі `valid`, тобто побічна умова, а не тест алгоритму | так |
| немає інструкції довільної комплексної сталої; корінь — вхід | `cz` → 0, `cone` → 1; інших комплексних літералів немає; корінь подано як аргумент `solve` | так |
| цілочисельні операції і довільний доступ на словах O(log(n+2)) біт коштують одиницю | `NOp` (add/sub/mul/div/mod/lt) → `Bill.word` (work = 1, `peak` стежить за величиною цілого); `look`, `len` — одиниця | так |
| сталі не залежать від n | `∃ cBound, ∀ n` (один сталий показник) у `DFTProgram` | так |
| немає обмеження на модуль комплексних коефіцієнтів і проміжних величин | `Ty.T (c _) = ℂ` (точні); `peak` стежить лише за цілими, не за модулем комплексних | так |
| немає тверджень про скінченну точність чи стійкість | у моделі немає жодного поля про похибку; обчислення точне в ℂ | так |
| добуток двох даних для DFT заборонено | `solve : Prog false …`; `cross` вимагає `allow = true` і недоступний при `false` | так |
| для згортки дозволено білінійні добутки даних | `ConvProgram` використовує `Prog true`; `cross (h : allow = true)` | так |

## Ціль (Goal.lean) ↔ thm:main і cor:decimal

| Препринт | Lean (`DFTProgram`, `TimeBounds`, `DFTGoal`) | Збіг |
|---|---|---|
| один детермінований алгоритм для кожного n і кожного x ∈ ℂⁿ | `∃ order solve W, … ∀ n>0, … ∀ x : Vec n, … result.val = dft n x` | так |
| достатньо подати ζ_{D*} з D* < 1024·n³ | `0 < d.val ∧ d.val < 1024·n^3`; `solve` отримує `root d.val` | так |
| час включає підготовку скалярів, побудову розкладу, індекси | `d.work + 1 + result.work ≤ W n` (робота order + корінь + solve) | так |
| час O(n(ln n)^θ(ln ln n)^{4−θ}) | `W' =O[atTop] paperTime`, `paperTime n = n·(ln n)^θ·(ln ln n)^(4−θ)` з натуральними логарифмами | так |
| наслідок: O(n(ln n)^{1−10⁻¹³}) = o(n log n) | `W' =O decimalTime ∧ W' =o nlogn` | так |
| поліноміальні межі на величину цілих і час (не окрема явна межа розміру масивів) | `W n + 10(n+2) ≤ cap`, `d.peak ≤ cap`, `result.peak ≤ cap`, `cap = (n+2)^cBound` | так |

## Що лишилось поза аудитом

1. **Семантика вартості як модель фізичної RAM.** Облік `Bill` у `Code.run`
   (comp додає 1; `loop` через `Bill.steps` платить 1 за ітерацію і стежить за
   `peak`; `tab`/`sow` нараховують довжину; `descend`/`depthRun` — обмежену
   рекурсію з нарахуванням глибини) — правдоподібний облік з одиничною вартістю,
   але відповідність «одна одиниця ↔ O(1) примітивних операцій RAM» є модельним
   судженням. Його не доведено тут; у принципі можна формалізувати іншу RAM-семантику
   й довести теорему про симуляцію, але такої незалежної формалізації ми не робили.
   Сам коментар «constant rescalings … are immaterial» міститься в `RAM.lean:15–16`
   (не в sec:model); у sec:model препринт стверджує лише, що всі сталі конвенцій не
   залежать від n.
2. **Тіло доведення.** `transform_main : DFTGoal` має import-closure з 89 модулів;
   історичний Lake build містив 9012 задач залежностей (це не 9012 доведених теорем). Ми його не перечитували; коректність бере на себе ядро Lean, а
   `#print axioms` підтверджує лише три стандартні аксіоми.
3. **Менша конкретна мережа у формалізації** (32 координати на фактор, обмеження
   2⁵⁰) відрізняється від network.tex; внутрішні lunch_big і alpha_theta дають
   O(n(ln n)^α(ln ln n)²), α=1−2·10⁻¹¹<θ; це окремо перевірено Lean-твердженням.
   Отже формулювання головної межі не послаблено. Відповідність самої мережі
   тексту network.tex не входить у цей аудит.

## Висновок

Означення `RAM.lean` і `Goal.lean` **вірно кодують** модель sec:model і
теорему thm:main препринту за всіма переліченими ознаками: розділені скалярні/даних
регістри, одинична вартість, ділення лише на скалярах з ненульовим знаменником як
побічною умовою, відсутність довільних комплексних сталих, єдиний поданий корінь
порядку < 1024·n³, точна комплексна арифметика без тверджень про стійкість, заборона
добутку даних для DFT, і межа часу з натуральними логарифмами. Залишковий розрив —
не в означеннях, а в (1) незамкненому модельному судженні про реалістичність обліку
вартості і (2) непрочитаному тілі доведення, яке перевіряє ядро.

## Уточнення аудиту 2026-10-14

DFTProgram обмежує величину цілих через peak і час через W, а не містить окремого лічильника загальної пам'яті масивів. `tab`/`sow` оплачують 1+довжину та роботу тіл. Тіла отримують початковий вхід та індекс, а не проміжну версію нового масиву; довільного `Atom.set` немає. Це узгоджується з інтерпретацією нового масиву з записами й доступом до вхідного масиву, але незалежної теореми симуляції фізичною RAM ми не доводили.

Головна ціль допускає порядок кореня D<1024·n³. `transform_main_order` будує receipt(n)<8·n³; receipt відрізняється від конкретної формули D_* препринту, але задовольняє цільову межу. Перевірка головного формулювання не сертифікує мережу network.tex та її конкретне Δ. Повний опис означень і цих меж узгоджено з §3.1 статті.
