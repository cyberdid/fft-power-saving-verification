## Середовище і запуск

Потрібен Python 3.12. `requirements-lock.txt` містить точні версії прямих і транзитивних
залежностей. SciPy обов’язковий: його імпортує `allength/compiler.py`.
`requirements-full-freeze.txt` — історичний запис системного середовища, не файл для встановлення.

Виконуйте з кореня проєкту:

```bash
python3 -m venv .venv
.venv/bin/pip install -r release/requirements-lock.txt
.venv/bin/pip check
bash release/run_all.sh full --output-dir /absolute/path/to/new-run
# Продовжити перерваний запуск із того самого середовища:
bash release/run_all.sh full --output-dir /absolute/path/to/new-run --resume
# Переглянути весь план без обчислень:
bash release/run_all.sh full --list
```

`PY=/path/to/venv/bin/python` дозволяє вибрати інший інтерпретатор. Без `--output-dir`
створюється новий каталог `release/out/run-<час>-<id>`; наявний каталог не перезаписується.
Невідомий режим завершується помилкою до будь-яких змін.

Запуск зберігає копію джерел у `source/`, експерименти виконуються з неї. `manifest.json`
містить хеші джерел, команди, час, коди завершення, хеші журналів і результатів.
Продовження перевіряє незмінність копії джерел, середовища та результатів успішних кроків;
невдалий крок запускається повторно. Окремі генератори, що дописують CSV, отримують власні
файли лише цього запуску. Тимчасові файли також залишаються в каталозі запуску.

Послідовність: усі тести → точні й чисельні експерименти → структурні перевірки →
`collect_v6.py --log-dir RUN/raw --output-dir RUN/data` →
`verify_tables.py --data-dir RUN/data --mode full` →
`make_figures.py --data-dir RUN/data --fig-dir RUN/figures`.
Збірник не читає архівні CSV замість відсутніх свіжих результатів. Файл `data/collection.json`
фіксує джерела та їхні хеші. Звернення тестів до архіву перевіряє сам валідатор;
чисельні та структурні результати запуску агрегуються виключно з `raw/`.

`full` охоплює core135 і включає циклотомічні матриці до r=32, C-слоти в Q(ζ_N) при r=4/8/16,
C-слоти в F_p до r=64 для всієї матриці і два вектори при r=128,
дві точності C-слотів при r=256, Тепліцеві слова при r=352/640/1024, фазові контроли,
обумовленість, корені, всі 12 структурних ширин, 72 топологічні випадки, модель глибини,
раунди та час/пам’ять при r=64/128/256/512. Результати порівнюються з округленими
числами рукопису; нові часи виконання перевіряються на додатність і правильне число гейтів,
оскільки залежать від машини та навантаження.

`quick` пропускає рівно шість найдовших експериментів: C-слоти r=256 при 450/550 знаках,
Тепліцеві слова r=640 при 400/500 та r=1024 при 600/700. Пропуски явно перелічені в плані
й результаті перевірки; цей режим не підтверджує повне відтворення статті.
Обидва режими виконують важкі кроки послідовно, з одним потоком BLAS. Оцінки часу й пам’яті
в статті стосуються попередньої машини та реалізації, а не гарантують ресурси іншого запуску.
Точний матеріалізований F_p при r=1024 у план не входить через високу витрату пам’яті.

Історичні порівняльні криві v4 на рисунках явно позначено як архівні; їхні константи не є
результатами свіжого строгого запуску. Мережу з `network.tex`, глобальний синтез і асимптотичний
виграш θ локальні експерименти не перевіряють.

## Рукопис і PDF

Числовий еталон для валідатора — `paper/article-ua.txt`. Англійська LaTeX-чернетка —
`paper/tex/en/main.tex`, PDF — `paper/article-en.pdf`; її збірка:
`TECTONIC=/path/to/tectonic bash paper/tex/build.sh en`. Українська LaTeX-версія ще готується.

З числового текстового еталона також можна побудувати окремий HTML/PDF за допомогою
попереднього скрипта. Після прийняття результатів і рисунків такий PDF можна
побудувати окремо (Chrome, Ghostscript; TeX не потрібен):

```bash
bash paper/scripts/build_pdf.sh /path/to/article.pdf
sha256sum -c release/SHA256SUMS
```

Рукопис і PDF не переписуються чисельним прогоном автоматично: таблиці є фіксованими
твердженнями, з якими порівнюються нові дані. Перед релізом перевіряються текст, арність
таблиць, сторінки PDF і актуальний маніфест. Поточний core-прогін full-20261013-r3 завершив усі 135 кроків. Його raw/data/figures, manifest, freeze та verification збережено без змін у `release/evidence/full-20261013-r3/` (копію джерел `source/` не включено; її хеші лишаються в manifest, див. `release/evidence/README.md`); незалежні перевірки — `release/evidence/independent-checks/`. У маніфесті лишено історичні абсолютні шляхи машини виконання; копію не можна продовжувати як новий запуск на іншій машині. Відтворюйте новий RUN командами вище. Старий текст у captured source є саме текстом на момент запуску; актуальний рукопис — `paper/article-ua.txt`.

Канонічні CSV у paper/data взято зі свіжого core-прогону; старі іменовані журнали в paper/data/v6 лишаються історичними. Зокрема timing.log підтримує історичну таблицю 8; timing.csv і raw/timing-*.log прийнятого core підтримують повторну таблицю 8a. collection.json зберігає оригінальні історичні шляхи і SHA; відповідні raw лежать у release/evidence/full-20261013-r3/raw. Перед остаточним складанням PDF рисунки перегенеровуються з цих свіжих CSV; порівняльні криві v4 лишаються позначеним архівом.

Окремий потоковий F_p r=1024 не входить до core135: команда і перевірки описані в `paper/data/supplemental/fp1024/README.uk.md`; checker — `paper/scripts/stream_exact_dft.py`. Результат checker v2: два ті самі вектори у двох полях, 0/4096 розбіжностей. Це необхідна умова, не доказ комплексної матриці або C-слотів r=1024. Не додавайте його заднім числом у core manifest/raw.

PDF рукопису (`paper/article-en.pdf`, `paper/article-uk.pdf`) і їхні LaTeX-джерела (`paper/tex/`) буде додано в наступному випуску. SHA256SUMS охоплює всі файли цього репозиторію, крім самого себе, і перевіряється з кореня командою `sha256sum -c release/SHA256SUMS`. Він засвідчує цілісність зафіксованих файлів, а не доведення теореми чи прийняття статті журналом.

## Lean

Використано Lean `leanprover/lean4:v4.34.1` і Mathlib
`d13f23b723b8a846827a245b89c10fc7d3f11612`. Джерела препринту:
`openai/math`, коміт `fd4aeeb2ee4fc729c18d98444fed42fd0529eeeb`.

```bash
mkdir lean-fft
cd lean-fft
cp /path/to/fft-power-saving-verification/release/lean/{lean-toolchain,lakefile.lean,lake-manifest.json,AxiomCheck.lean} .
mkdir -p OAI/Computability
cp -r /path/to/openai-math/lean/OAI/Computability/FourierTransform OAI/Computability/
cp -r /path/to/openai-math/lean/OAI/Computability/FourierCircuit OAI/Computability/
lake exe cache get
lake build OAI.Computability.FourierTransform.Main
lake env lean AxiomCheck.lean
```

Для двох головних теорем очікуються лише `propext`, `Classical.choice`, `Quot.sound`.
`lean/MODEL_AUDIT.md` звіряє означення моделі з текстом препринту; це окрема перевірка
від читання тіла доведення. Компіляція головної теореми покриває її залежності, а не всі
допоміжні модулі, які не імпортує головна ціль.
